# Week 6 관찰

## Task 1
support 50에서 최고 confidence 규칙은 1468→0으로 0.83871이고, 역방향은 0.003976이다. 1468 구매자에게 0을 제안하는 방향이 더 유용하며, confidence는 대칭이 아니다.
lift는 1.28243, 강의의 관심도는 0.18471이다. 상품 0의 기본 구매율이 0.654라서 높은 confidence만으로 강한 관계나 인과라고 단정할 수 없다.
전체 가능한 쌍은 1,999,000개, Pass 1 후 1,849개 상품의 가능한 쌍은 1,708,476개다. 실제 카운터는 관측된 820,259개만 만들었고, 규칙 생성도 singleton count를 재사용해 두 번의 순회로 처리했다.

## Task 2
기본 데이터는 support 1까지 완료했다. 추가로 10만 baskets·2만 items에서 낮추자 support 3에서 추가 Python peak 1.24GB로 사전 예산 1GiB를 넘겨 이후 측정을 멈췄다. 시간 60초보다 메모리 예산에 먼저 도달했으며, 물리 RAM 고갈을 측정한 것은 아니다.
기본 데이터의 400→200→100→50에서 카운터는 5.54→4.67→3.00배, 정답은 3.12→2.89→2.85배씩 늘었다. support 50의 정답은 6,397개지만 카운터는 820,259개여서 비빈발 후보의 비용이 크다.
support 25 이하에서는 기본 데이터의 카운터가 포화되어도 정답과 반환 결과 메모리는 계속 늘었다. 두 데이터의 표·곡선·중단 기준과 측정 범위는 explosion.md에 구분해 기록했다.

## Task 3
2,097,152개의 bucket을 사용해 pair counters를 820,259→7,243개(99.12%) 줄였으며, 정답 6,397개와 각 support count는 같았다. 16,384 buckets에서는 모든 bucket이 빈발해 필터 효과가 사라졌다.
bucket은 8MiB, bitmap은 0.25MiB이고 압축 순간 둘 다 존재한다. 이를 포함한 추가 Python peak는 107.88→8.87MB로 약 91.78% 줄었고, 절대 support 50에서는 5천~1만 baskets 사이에서 PCY가 유리해졌다.
bench.py를 그대로 실행해 strong을 얻었다. PCY는 hash·bitmap 처리로 baseline보다 느렸으며, 카운터 감소와 실행 시간 개선은 구분해야 한다. 상세 메모리 비교는 pcy_memory.md에 기록했다.
